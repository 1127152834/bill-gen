# 验收标准（Rubric）

没有这三条，改动就无法证明是变好了还是只是换了种假法。

## 门槛 1：闭合率 = 100%（一票否决）
- `begin + Σcredit − Σdebit == end`，分单位整数比较
- 逐行余额链连续
- 跨月接续 `end(T) == begin(T+1)`
- 摘要分项 = 明细分组合计
- 任意一条不过 → 不出片，回求解器

## 门槛 2：分布回归（KS / 卡方，p > 0.01）
对 500 个生成月与真实参数表逐项检验：

| 指标 | 真实参考 | 判据 |
| --- | --- | --- |
| 类目占比 | BLS CEX 按收入五分位 | 每月落在信封 ±35% |
| 到访间隔 CV | 0.6–1.4 | < 0.35 视为均匀撒点（假） |
| 整美元占比 | 12%–25% | > 30% 视为机器味 |
| 同商户频次 | 长尾（Top3 占 40–60%） | 平均分布 = 假 |
| 周末消费占比 | 30%–42% | 偏离 > 8pp 报警 |
| 金额分位 | 参数表 P25/P50/P75 | 偏差 > 25% 报警 |

## 门槛 3：辨识率 ≤ 65%
- 素材：20 张真实账单（去标识）+ 20 张生成账单，同格式混排
- 评审：3 个不同模型 + 1 个人类，各自独立判断「真/假」
- 记录：整体辨识率、按银行拆分、被指出的**具体线索**（线索本身最有价值）
- 当前状态：**未测**（第一步要先建立基线）

## 附加：格式契约通过率 = 100%
`contracts.check()` 对每家模板零问题；契约缺失视为不通过。

## 记录方式
每轮把三个数字写进 `job-summary.json`：
```json
{"closure": 1.0, "distribution_p": {"dining": 0.21, "fuel": 0.08}, "discrimination": null}
```
`discrimination` 为空表示还没做盲测——**不要假装它通过了**。
