# 统一前端工作台

## 设计与结构

首页由模板侧栏、文档操作栏、数据编辑区和分页预览区组成。暖灰背景、深墨色导航、青绿强调色；桌面并排编辑与预览，小屏纵向排列。没有外部字体、CDN 或 JavaScript 框架运行依赖。

- `src/billgen/server/web/index.html`：语义化页面与对话框。
- `src/billgen/server/web/app.css`：设计变量、组件及响应式布局。
- `src/billgen/server/web/app.js`：模板注册表、结构化编辑、草稿、JSON、预览、分页和下载。
- `src/billgen/server/web/legacy.css` / `legacy.js`：原专属编辑器的独立视觉层与导航；保留原 ID、事件及生成流程。
- `/web-assets/` 只提供明确白名单中的资源；资源随 wheel 打包，无前端构建服务。

## 操作与兼容

11 个后端模板复用 `/api/v1/templates` 和预览/导出接口，数据不做跨模板格式转换。对象按需展开，数组分页显示并支持添加、复制与删除，字段保留字符串/数值/布尔/null 类型。高级 JSON 用于复杂结构或未知字段。

Alliant 与 Ally 在内嵌编辑器中运行原浏览器 PDF 引擎；不假装支持服务端渲染。其他模板的「完整模板编辑器」保留原有预设、覆盖率、专属字体、保存和其他高级操作入口。旧入口获得共享外观与折叠表单、适配预览等辅助操作。

草稿按模板存于当前浏览器 localStorage；统一工作台不会自动覆盖旧编辑器的服务端数据文件。导入导出 JSON 是两者交换数据的方式。保存草稿与生成 PDF 是不同状态：修改后明确标注当前预览过期，显式点击「生成预览」或 Cmd/Ctrl+S 更新。下载 PDF 总是按当前有效数据调用导出。

## 状态完整性

- 无效 JSON 保留原始输入，并阻止生成；输出设置独立更新，不把无效文本替换成旧数据。
- 预览序号和文档修改版本保护过期请求；模板载入序号保护快速切换和导入/重置竞态。
- 非法数字通过字段校验反馈，不静默转换为空或零。
- 草稿空间异常提示用户导出 JSON；图片任务过期提示重新生成。
- 恢复示例、覆盖导入、带未预览修改切换模板提供确认。

## 验证

自动测试覆盖首页与资源 MIME / 路径白名单、wheel 资源、旧入口 HTML 注入以及原 API/JS 不受注入影响。状态回归使用 Node VM（有 Node 的环境执行）。Python 引擎的像素/文本黄金回归继续使用现有测试。

浏览器检查覆盖分页预览、缩放、JSON 校验及错误恢复、PDF 实际下载、静态模板内嵌与窄屏横向溢出。Docker 仍使用现有数据卷，不改变持久化目录。
